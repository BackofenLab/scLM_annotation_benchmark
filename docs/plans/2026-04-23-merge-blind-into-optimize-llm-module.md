# Merge `origin/blind` into `optimize-llm-module` — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Produce a single branch `integrate-blind` that contains both `optimize-llm-module`'s LLM/pipeline work and `origin/blind`'s Docker/model-fix work, with a green smoke test.

**Architecture:** Off-branch merge (new `integrate-blind` from `optimize-llm-module` HEAD). Single `git merge --no-ff origin/blind` surfaces all conflicts at once. Conflicts resolved bucket-by-bucket with interactive user review; priorities are broad (ours for LLM + download/preprocess/subset; theirs for Docker envs + model bug fixes) and applied per-hunk, not wholesale per file.

**Tech stack:** git, nextflow, python (the pipeline bin/ scripts), conda envs, optional Docker.

**Design doc:** `docs/plans/2026-04-23-merge-blind-into-optimize-llm-module-design.md`

**User constraints to respect throughout:**
- Never delete or force-push `blind` / `origin/blind`.
- No `Co-Authored-By` trailer in any commit message.
- No `--amend` on the merge commit; fix-ups go as follow-up commits.

## Task 3: Initiate the merge and survey conflicts

**Step 1: Run the merge.**

Expected: non-zero exit, message "Automatic merge failed; fix conflicts and then commit the result." plus a list of CONFLICT lines.

Run: `git diff --name-only --diff-filter=U | tee /tmp/conflicts.txt`

**Step 3: Classify conflicts into the 9 buckets from the design doc.**

Do this as a checklist — walk the conflict list and tag each file with a bucket number. Present the classification to the user as a compact table before touching any files. Buckets (from design Section 2):

**Step 4: Pause for user confirmation on ordering.**

Default order for resolution: 9, 8, 5, 4, 7, 6, 3, 2, 1 (low-risk → high-risk, so context for pipeline decisions is strongest by the time we get to them). User may reshuffle.

## Task 4: Resolve bucket 9 — cache artifacts

**Files:** every conflicted file under `cache/`.

**Step 1: List bucket-9 conflicts.**

Run: `git diff --name-only --diff-filter=U | grep '^cache/' || true`

**Step 2: Accept ours en bloc.**

Rationale: these are generated outputs; they get regenerated by the pipeline. Taking ours keeps the repo's current cached state consistent with what `optimize-llm-module` runs produce.

For each conflicted path P in the bucket:
```
git checkout --ours -- "$P"
git add -- "$P"
```

For rename/delete conflicts (where one side deleted the file), decide per file:
- If ours deleted and theirs modified: `git rm -- "$P"` (keep our deletion).
- If ours modified and theirs deleted: `git add -- "$P"` (keep our modification).

**Step 3: Sanity check.**

Run: `git diff --name-only --diff-filter=U | grep '^cache/' || true`
Expected: empty output.

**No commit.**

## Task 14: Smoke test

**Step 1: Ensure `nextflow.config` reflects the smoke-test conditions.**

Required runtime state:
- `datasets = ['HFRA']`
- `subset_size = 1000`
- `subset_strategy = 'random'`
- Only `celltypist` (blind variant) model enabled.

If the merged `nextflow.config` does not already look like this, stage ephemeral edits WITHOUT committing them (we don't commit smoke-test-specific config).

**Step 2: Run the pipeline.**

Run:
```
nextflow run main.nf -profile local
```

Expected: pipeline reaches `evaluate` / `aggregate` and produces predictions for HFRA under `cache/models/predictions/celltypist_blind/HFRA/1000_random/` (or equivalent path the new cache-keying scheme produces).

**Step 3: Verify outputs.**

Run:
```
ls cache/models/predictions/celltypist_blind/HFRA/
```
Expected: a directory containing a `predictions.csv` from this run.

**Step 4: Revert any ephemeral nextflow.config edits, if any.**

Run: `git checkout -- nextflow.config` (only if you made smoke-test-only edits).

**If the smoke test fails:**
- Diagnose the failure. Do NOT amend the merge commit.
- If the fix is an obvious merge-resolution error, add a new commit on top (`fix(merge): ...`).
- If a whole bucket was resolved wrong, `git reset --hard <merge-commit>^` is unsafe (discards the merge). Instead: `git checkout <merge-commit> -- <files>`, re-resolve the affected files, commit as `fix(merge): re-resolve <bucket>`.
